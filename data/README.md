# data/

Two collection campaigns, two layouts. Both are committed in full.

```
data/
  pilot-20261029/          24 sessions, 60 s, 8 idle / 8 static / 8 motion
    idle/                  <collector-name>.npz + .json
    static_presence/
    motion/
    manifest.csv           generated by tools/validate_sessions.py
  dorm-v2/                 8 sessions, 90 s, 3 idle / 3 static / 2 balcony
    idle-01-raw.npz        + .json sidecar
    static-presence-01-raw.npz
    balcony-01-raw.npz     label: interference_balcony (through-door)
```

## `pilot-20261029/` — one folder per label

`label` must equal the folder name; mixed labels inside one file are rejected.
Files keep the collector's own names, because renaming by hand loses the chip,
subcarrier count, device id and timestamp encoded in them.

Required keys: `csi_data` (frames × 64 amplitudes, float) and `timestamps`
(seconds); `label` when present is checked against the folder.
Sidecar fields are listed in `docs/DATA-COLLECTION-PLAN.md` §3.

## `dorm-v2/` — flat, label in the sidecar

`<label>-NN-raw.npz` plus `.json`. This set is **not** consumed by
`validate_sessions.py`; it is read directly by `tools/presence_v2.py`, and its label
lives in the sidecar (`interference_balcony`, `idle`, `static_presence`).
`interference_balcony` is a registered label: the door was closed and the person
walked on the balcony outside.

Do not commit raw `.pcap` captures. Do commit the `.npz` files while the total stays
under about 50 MB; otherwise commit only `manifest.csv` and the hashes.
